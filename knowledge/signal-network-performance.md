# 何を変えたか

`src/world/trafficControl.ts` の `buildSignals` は、交差点として扱う OSM の信号を 1 つずつ、道路網の全部の交差点（3 本以上が集まる節点）と比べ、25 m 未満の最も近い物につけていた。信号の記録は道路網より広い範囲から来るので、外の信号でも全部の交差点を回っていた。

交差点の座標を集めるときに範囲（最小と最大の x・z）も取り、信号がその範囲から SIGNAL_SNAP_M 以上外なら、比べずに次へ進む。範囲は、照合が読むのと同じ交差点の一覧から作る。[^tests]

採らなかった方法: 交差点の格子（範囲の中の遠い交差点も省ける）。範囲の確かめだけで、外の信号の分を数行で省け、照合の順と厳密な < 25 m をそのまま残せる。

# 計測（1 本、2 地域、旧と新を交互に 30 回ずつ）

値は setNetwork の同期の部分（信号・単路の横断・一時停止。模型は generator で、回さない）の 1 回の時間。[^run]

| 地域   | 区間  | 信号（記録） | 交差点 | 旧 中央値 / 95 % / 最大 | 新 中央値 / 95 % / 最大 | 合計（30 回）    |
| ------ | ----- | ------------ | ------ | ----------------------- | ----------------------- | ---------------- |
| 東京駅 | 1,189 | 680          | 479    | 5.4 / 6.7 / 7.1 ms      | 4.2 / 4.7 / 5.0 ms      | 163.6 → 124.5 ms |
| 吾妻橋 | 2,373 | 623          | 1,092  | 9.6 / 10.0 / 10.4 ms    | 4.8 / 5.2 / 5.4 ms      | 284.0 → 139.6 ms |

- 狙った値（道路網の組み立て 1 回）: 東京駅 −1.2 ms（−22 %）、吾妻橋 −4.8 ms（−50 %）。交互の 30 回とも新しい方が速い。計画のマージ前の条件（20 % 以上、1 ms 以上、全往復で同じ向き）を満たす。東京駅は線に近い（−22 %、−1.2 ms）。
- 一致: 接近路（区間・向き・位置・種類・軸・制御器）、区間ごとの一覧、信号の数、制御器の共有、13 の時刻の灯火の状態、次の停止の 726,671 値（東京駅 217,992・吾妻橋 508,679）が、30 回とも旧処理と同じ。
- 信号の記録（OSM のタグ）は、ゲームが setNetwork に渡す物をそのまま使った（記録が無いと、全部の信号を交差点の物として読み、ゲームと違う仕事になる）。

# 確かめていないこと

- 道路網の組み立て全体（模型・コライダー・路面）での割合。これは信号の照合の部分だけ。
- ほかの地域（信号が道路網の内側に多い所では、省ける分が減る）。
