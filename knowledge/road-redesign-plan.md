## 1. コンテキスト

- 形状は GSI z16 中心線だけで、`lvOrder!==0` を捨てている（`src/world/roadTiles.ts:60`）。高架・層・縦断・ランプ・車線接続の概念が無い。

- 車線の定義は `src/world/laneChange.ts` に一本化済み（knowledge/turn-paths.md）。これを保つ。
- 性能の制約（knowledge/road-streaming-performance.md）: FrameWork 4 ms、Worker は最新 1 件、世代整合、原点移動は reanchor、trimesh の再生成は高い（歩道で 495 ms の前例）。

## 3. 目標アーキテクチャ（共通）

### 3.1 データモデル

```
RoadLine（既存に追加）
  source: "gsi" | "osm"
  cls: "street" | "expressway" | "ramp"     // 機能。kind（行政区分）は残す
  structure: "ground" | "viaduct" | "tunnel" | "cut"
  level: number                             // 0 地上。交差の上下関係と節点キーに使う
  section: CrossSection
  xid?: string                              // 高速チャンクの安定 ID（世代をまたいで不変）
  ref?, limit?                              // 路線記号、OSM maxspeed
Segment（追加）
  elev: number[] | null                     // 点ごとの路面高（ローカル y）。pts.y は 0 のまま
  bank: number[] | null                     // 片勾配
CrossSection（区間内一定。変化点で区間を切る）
  lanes, laneWidth, shoulderL, shoulderR, median
  aux?: { side, kind: "accel"|"decel", widthStart, widthEnd }   // テーパー
  marks: { centre, lane, edgeL, edgeR }     // 線種・色・寸法クラス
  basis: "jartic" | "osm" | "width" | "statute"                 // 根拠（QA とテストが読む）
LaneLink（節点ごと、ID の配列で持ち構造化クローン可）
  [fromSeg, fromLane, toSeg, toLane, kind: "through"|"merge"|"diverge"]
```

- `line.width` は `section` から導く値として残し、既存の利用箇所を壊さない。
- `laneChange.ts` を `CrossSection` の窓口にする（車線幅 = `laneWidth`、左端 = 幅/2 − `shoulderL`）。描画・違反・経路・自動運転は今までどおりここだけを見る。
- `pts.y = 0` を保つ理由: XZ 距離の計算が全域にあり、y を入れると壊れる。高さは `graph.surfaceY(seg, s)` で引く。

### 3.2 層と空間検索

- 節点キー: OSM 由来は OSM ノード ID、GSI 由来は従来の座標丸め。立体交差は自然に分離される。
- 既存の `nearest` / `carriagewaysAt` の既定を「地上（level 0・ground）のみ」にする。旧来の呼び出しは挙動不変。
- 新設 `nearestOnSurface(p3d, range, accept)`: |p.y − surfaceY| ≤ 2.5 m の垂直ゲートつき。自車・違反判定・交通の現在区間はこちらへ移す。

## 4. 高速道路生成システム（一般道とは別モジュール）

構成: `src/expressway/`（純粋な TypeScript。three.js と DOM に依存しない線形・断面・検証）、`scripts/expressway.ts`（tsx。OSM pbf → `public/data/expressway/<x>-<y>.json` と `meta.json`）、`src/world/expresswayDeck.ts`（実行時の押し出し・コライダー）。

### 4.1 入力と正規化

- OSM `motorway` / `motorway_link`（全 oneway・上下別）。本線を ref と直進性で「線形チェーン」に連結し、距離程 s を振る。
- 車線数: OSM `lanes`、無ければ本線 2・ランプ 1。設計速度 V: `maxspeed`（無ければ 60、ランプ 40）。区分: 第二種第二級（都心部）を既定。
- GSI の `rdCtg=3` / `motorway=1` の線は実行時に全て捨てる（OSM と二重になるため）。
- 事業者名を含む `name` は落とし、`ref`・`destination`・`motorway_junction` の name / ref だけを残す。

### 4.2 平面線形

- OSM 折れ線を、横ずれ ε ≤ 1.5 m の範囲で曲率変化を最小にする平滑化にかける（曲率が弧長にほぼ線形 = 緩和曲線相当）。5〜20 m の測点に標本化する。
- 現地の半径は動かせない。得られた R が R_min(V) を下回る区間は V を 60→50→40 と下げ、それが規制速度の上限と片勾配に効く。なお不足する箇所は理由つきの許可リストに載せる。
- ランプは 28条4項で幅・半径の適用外。ただし走行できるよう R ≥ 15 m を下限にする。
- 上下線は別々に平滑化するので、同じ層の車線域が重ならないことを検査する。近接する対は床版を一体化し、中央に分離壁を 1 本置く（`water.ts` の `otherDeckAt` と同じ考え）。

### 4.3 縦断線形（要点）

高さは自前で決めるので、ここは令を厳守する。

1. **拘束を集める**
   - 等式: 地表への擦り付け点（`structure` が ground に切り替わる点、ランプ端）は z = 地表・勾配連続。構造物上書き（4.6）。分合流点はランプの z・勾配・片勾配 = 本線の値。
   - 下限: 交差する下の対象（地上道路、下層の高架、水面）+ 建築限界 4.5 + 桁高（仮定）。上限: 上層の桁下 − 4.5。
   - `layer` は交差点での上下の順序づけにだけ使う。タグの切り替わり節点で段差を作らない。高架の目標高は「標準桁下高（仮定）」で、交差の所だけ必要なだけ上げる。
2. **PVI 法で解く**: 縦断変化点を置き、接線の勾配を 20条の値以下にする。変化点ごとに放物線の縦断曲線を入れ、長さ L = max(22条の最小長, R_min × |勾配差|) とする。本線を先に解き、ランプは本線の値を境界条件にして解く。
3. **解けないとき**の順序: 特例値の勾配 → V を下げる → 目標高を下げる（下限まで）→ 診断を出して失敗。黙って破らない。
4. **片勾配**: e = clamp(V²/(127R) − f, 0, 10 %)。f は仮定。緩和区間（18条）で直線的に擦り付け、合成勾配（25条）を検査する。物理への影響があるので機能フラグで有効化する。

出力は測点ごとの `[lon, lat, 標高, 片勾配]`、区間属性、節点、`LaneLink`、標識の設置点。チャンクは 300 m 以下で安定 ID（`<チェーン>:<k>`）を持ち、節点・断面変化点で切る。

### 4.5 実行時（デッキ・コライダー・世代）

- 断面を測点に沿って押し出す: 床版、壁高欄、遮音壁、桁（箱桁の下面）。橋脚は InstancedMesh で、位置は距離程から決める（再構築で動かない）。地上の車道・水面に落ちる脚は前後にずらし、並走する地上道路があれば中央寄りの単柱にする。
- **チャンク単位でキャッシュ**し、300 m ごとの道路網再構築では作り直さない。半径で出し入れする（描画 約 1.5 km、コライダー 約 400 m）。生成は FrameWork のステップに分ける。
- コライダー: 床版上面と壁の trimesh を、チャンクごとの fixed body に。橋脚は cuboid。原点移動は `reanchorBody`（`water.ts` と同じ行列の持ち方）。
- **世代整合**: グラフの区間もデッキも同じ不変チャンクの純関数なので、世代が食い違っても形は一致する。`installRoadNetwork` に「expressway」段を network の直後・surface の前に入れ、コライダーの無いチャンクを走行可能として公開しない。ワープの着地もデッキの完成を待つ。
- Worker には近傍チャンクを配列で渡す（参照は `xid`、座標は配列）。
- ランプ端: OSM で一般道 way と共有する節点を、実行時に最寄りの GSI 地上区間（15 m 以内）へ射影して区間を割り、共有節点にする。失敗は `ramp_unattached` を記録し経路から外す。
- トンネル・掘割（最低限）: 当面は `structure` を持つだけで走行不可・経路から除外し、坑口手前に通行止めの柵を置く。P9 で、水面と同じ地形の切り抜きと、床・壁・天井つきの箱で通す。

### 4.6 構造物上書き（レインボーブリッジ）

汎用の仕組み `structureOverrides` として持つ（今後の特殊橋にも使う）。

- 入力: `landmarks.json` の `deckLevels`（上層・下層それぞれの中心線・標高・幅、区間の範囲）。ビルドの依存は「ランドマーク生成 → 高速道路データ生成」。
- 区間内: 平面線形を `deckLevels` の中心線に、縦断をその標高に**等式で拘束**する。床版・壁高欄・区画線・コライダーは本システムが作り、**橋脚と桁の自動生成を抑止**する（主塔・ケーブル・補剛トラス・アンカレイジはランドマーク側）。
- 境界: 標高と勾配を等式拘束としてアプローチ高架の PVI 解に渡す。アプローチ（芝浦側のループを含む）は通常の高架として橋脚つきで作る。
- 検査: 拘束区間で z の差 ≤ 5 cm、幅が `deckLevels` に収まる、境界で T3。OSM と `deckLevels` の中心線が 3 m を超えてずれたらビルドを失敗させ、両担当が気づけるようにする。`deckLevels` が無ければ通常生成に落として警告する。
- **下層の一般道（臨港道路）**: GSI では `lvOrder≠0` で落ちるので、OSM の該当 way を上書き定義で指名し、同じコンパイラに `cls: "street"`・`structure: "viaduct"`・第四種の断面で通す。両端は 4.5 のランプ端と同じ方法で地上の GSI 区間へつなぐ。規制速度は OSM `maxspeed`。歩行者と路端設備は当面置かない（`allowsPedestrians` = false、遊歩道は範囲外）。一般の「陸上高架の一般道」へ広げるのは今回の範囲外で、指名した構造物だけにする。

### 4.7 区画線

`MarkingPlan`（純粋。区間ごとの「種別・オフセット・区間・線種・色・幅」）を `CrossSection` と規制から作り、地上用（地形追従）とデッキ用（押し出し）の 2 つの描画に渡す。法令準拠は `MarkingPlan` のテストで保証する。

- 車道外側線 103: 白実線 0.20 m、車線域の両端（外側が路肩）。
- 車線境界線 102: 白破線 0.15 m。線長・間隔は令の範囲（3〜10 m、1〜2 倍）内の定数。8 m / 12 m は範囲内だが実務値は未確認と注記。
- 分合流部: 幅 0.30〜0.75・線長 2〜5・間隔 1〜1.5 倍の太い破線を、本線と変速車線の境に。
- 導流帯 107: ノーズ手前の三角域に外枠＋斜線。寸法は別表の例示図（scratchpad `egov/img/`）から転記。
- 黄線（進路変更禁止）はデータが無いので引かない（既知の欠落として記録）。

### 4.8 標識と名称

- 規制: 自動車専用 325（入口）、最高速度 323（合流後と `maxspeed` の変化点）。最低速度 324 は置かない（75条の4 は高速自動車国道のみ）。
- 案内: 入口の方向 103-A/B と入口の予告 104（一般道側）、110-B（100〜600 m 手前）、111-B（100〜500 m、車線上方）、112-B（300 m 以内）、出口 113-A/B（ノーズ）、JCT は 107-A/B。緑地白字、出口番号は白地緑字。設置点はビルド時に `motorway_junction` と `destination` から作る。

- 支柱（門型・壁高欄付けの F 形）は `scripts/blender/` で作り台帳に登録。板の文字は既存の案内標識の経路（Noto Sans JP / Overpass）を使う。
- **名称層** `src/game/roadNames.ts`: 事業者名は i18n キー（日「都市高速」、英は実在の英語名と重ならない語）。路線記号と出入口・JCT 名は OSM のまま。ロゴ無し。「首都高」「首都高速」「Shuto」「Metropolitan Expressway」が src と `public/data/expressway` に無いことをテストで検査する（`tests/socialBanned.ts` の前例）。AGENTS.md に今回の例外を追記する。

### 4.9 法規の判定

`main.ts` に足さず `src/game/expresswayLaw.ts`（純粋・テストつき）へ。点数・反則金は e-Gov で確かめてから入れる（knowledge/road-traffic-law.md の方針）。

- 75条の5: 後退、転回、逆走。
- 75条の6: 加速車線から入るとき本線車の進行を妨げた（本線車の急制動・車間で判定）。
- 75条の7: 変速車線を使わずに出入りした。導流帯を踏んだだけでは記録しない（保守的に）。
- 75条の8: 本線・路肩での駐停車。渋滞と危険防止の停止は除く。
- 速度: `maxspeed` を規制速度、無ければ法定 60。最低速度は判定しないことをテストで固定。

## 5. 一般道の法令準拠

- **車線数の一本化**: `resolveSection(line, evidence)` だけが決める。優先は JARTIC 車両通行帯数 ＞ OSM `lanes`（`lanes:forward/backward`）＞ 幅員推定。`regulations.ts:744` と `guidePlan.lanesFor` の二重化を解消する。OSM は既存の `public/data/turnlanes` に列を足し、JARTIC と同じ対応付けに載せる。
- **幅員補正の一元化**: `carriagewayWidth()` に集約し、`w/2−2` 等の場当たり補正を消す。車線数が分かれば「車線×幅＋路肩＋中央帯」を名目幅で頭打ちにする。歩道は従来どおり PLATEAU の多角形で決める（knowledge/sidewalks-and-footbridges.md）。
- **寸法**: 中央線・車線境界線・外側線を `roadStandards.ts` の範囲内の定数に。路肩は第四種 0.5 m とし、外側線は「幅/2 − 路肩」（現行の −0.4 を置換）。
- **交差点**: 今回は既存の切り欠きと停止線を断面に合わせるまで。交差点ポリゴンと右折車線の拡幅は範囲外。
- 実データの回帰テストを新設（`tests/roadSection.test.ts`: 3 地点の区間で車線数・根拠の分布をスナップショット）。

## 7. 多視点レビューの収束ループ

- **自動化**: `scripts/qa/views.mjs` と視点表 `scripts/qa/expressway-views.json`（地点・チャンク・視点・時刻・天気）。開発用フック `window.__game.debug.camera` を足す。各コマに「あるべき状態」の JSON（車線数・幅・規制速度・断面の根拠・前方の標識）を添える（`drive.mjs` と同じ形）。レシピは `capture-views`。road-qa スキルに視点の節を足す。
- **視点**: 運転席／後方追従／真上の俯瞰（区画線の幾何）／高架下から見上げ／側面（縦断の折れ）／合流（ランプ側・本線側）／分岐ノーズと案内標識の正面（100・50 m）／夜・雨／遠景（LOD の切り替わり）／レインボーブリッジ（床版とトラスの合い）。
- **数値の探り**（画像だけに頼らない）: 自動運転で走らせた上下加速度の RMS、10 m ごとの勾配差の最大、床版のレイ格子の穴、桁下の実測、最長フレーム。
- **チェックリスト**: 法令（線種・幅・色・設置距離・標識番号と色・名称の禁止語）／幾何（隙間、z ファイティング、浮いた脚、車道上の脚、建物・地面との貫通、継ぎ目）／テクスチャ（繰り返し、伸び、継ぎ目、ちらつき、濡れ）／走行（落下、段差、合流の挙動）／性能。
- **回し方**: 観点ごとに別のレビュー担当を並列に。指摘は `.qa/reviews/<周>.jsonl`（id・視点・重大度・状態）。直したら回帰テストかチェック項目を足す。
- **収束**: 全視点で Critical / Warning の新規指摘が **2 周続けて 0**、かつ数値の閾値を満たす。6 周で収束しなければ設計へ差し戻す。結果は knowledge に OKF で残す。

## 9. Why not と未確認・リスク

- **なぜ実行時に線形を解かないか**: 読み込み範囲で結果が変わり、走行中に床が動く。ビルド時なら決定的で、検証もできる。
- **なぜ `layer` × 固定高にしないか**: タグの切り替わり節点で段差ができる。高さは交差の拘束から決める。
- **なぜ厳密なクロソイド要素に当てはめないか**: OSM の頂点の揺れで要素分割が不安定。許容幅つき平滑化で同じ走行性を得られ、出力形式（測点）は変わらないので後から替えられる。
- **なぜ 47 か所を一括で解除しないか**: 意味が 5 種類あり、歩行者・路端設備は法的に恒久除外。
- **なぜ区画線をテクスチャに焼かないか**: 車線数・規制で変わり、判定と同じ定義から作る必要がある。
- **DEM が同梱不可の場合の代替**: 高さを「擦り付け点の地表を実行時に引き、その間は相対高」で持つ。桁下の事前検証を失うので劣る。
- **未確認**: 変速車線長、桁高・橋脚間隔・壁高欄高・標準桁下高、遮音壁の配置、非常電話の間隔、破線の実務値、摩擦係数 f、合成勾配の表、PLATEAU の首都高の網羅、`layer` も `bridge` も無い 211 本の way の実態（地上か掘割か）、OSM `lanes` の無い 164 本。
- **リスク**: 生成した高架と PLATEAU 建物の貫通（視点レビューで検出、直せない所は許可リスト）、二層区間、上下線の重なり、地理院タイル更新による擦り付け点のずれ（実行時に地表へ混ぜて吸収）、高架下の雨・影・街灯の干渉。

## 10. 帰結と判定

- 道路は「断面プロファイルを持つ層つきグラフ」になり、首都高はビルド時に検証済みの線形から押し出される。法令値は 1 か所で条文つき、仮定は別の場所で未確認と明示される。
- 後続: knowledge に `expressway-generation.md`・`road-standards.md` を追加（tag は `tags.yml` に登録）、AGENTS.md に名称の例外と高速道路データの再生成手順を追記。
- **判定: 条件付き推奨。** 条件は (1) DEM 由来値の同梱の法務確認、(2) P1 の試験区間で縦断が T1〜T5 を満たして解けること、(3) P1 の性能が基準内であること。
