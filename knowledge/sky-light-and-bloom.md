# 何をどこでしているか

| 役割                                                                 | ファイル                        |
| -------------------------------------------------------------------- | ------------------------------- |
| 太陽高度と雲量から光の配分を決める純粋関数                           | `src/world/skyLight.ts`         |
| Sky.js のフラグメントシェーダーへの追加（夜・星・薄明・雨・霞）      | `src/world/skyShader.ts`        |
| 空から作る環境マップ（`scene.environment`）と描き直しの条件          | `src/world/skyEnvMap.ts`        |
| 上の三つを毎フレーム当てる。天気の切り替えを 25 秒かけて動かす       | `src/world/environment.ts`      |
| 霧の色を放射輝度として扱う（トーンマップと sRGB 変換を霧にも掛ける） | `src/world/atmosphere.ts`       |
| ブルーム                                                             | `src/world/bloom.ts`、`main.ts` |
| レンズフレア（webgpu ブランチ）                                      | `src/world/lensFlare.ts`        |

画質の設定（`src/graphics.ts`）の「空の映り込み」と「光のにじみ（ブルーム）」で切り替わる。

- 空の映り込み: 高 = 256 の環境マップを太陽 1° ごと（最短 0.4 秒おき）に描き直す。低 = 64 を 3° ごと（最短 3 秒おき）。なし = 以前の RoomEnvironment（一度だけ）。高となしは PMREM の大きさが同じ（256）なので切り替えても材質のシェーダーは再コンパイルされない。低との切り替えでは再コンパイルされる。
- 光のにじみ: 高 = 半分の解像度から 1/32 まで 5 段。低 = 1/4 から 4 段。なし = コピーも含めて何もしない。
- レンズフレア（webgpu ブランチ）: あり（最高・高）/ なし（中・低）。夜の灯りのゴーストは光のにじみ も あり のときだけ（ブルームの段から作る）。

# 光の配分（skyLight.ts）

- **太陽の色**: 空気質量 m（Kasten & Young の近似。天頂 1、10° で 5.6、地平で 38）[^kasten-young] と、Sky.js と同じ三原色（680・550・450 nm）のレイリー光学的厚さ（0.041・0.097・0.221）[^bodhaine] に都市の薄いエアロゾル（Ångström β = 0.04、α = 1.3）を足した τ で、透過 exp(−τ(m − 1)) を天頂の太陽で白に合わせる。指数に順応の 0.6 を掛ける（1 のままだと 3° の太陽が分光計どおりの濃い赤で、夕焼けの写真の色にならない）。結果は 50° でほぼ白、9°（朝）で (1, 0.79, 0.50)、3°（夕方）で (1, 0.52, 0.15)（いずれも線形）。
- **太陽の強さ**: 2.85 × √輝度 × 円盤の沈み（+1.5° から −0.8°）。昼の 2.8 は以前と同じ。夕方 3° で 1.39。雨で 0.32 倍。
- **天空光**（HemisphereLight）: 昼は sin(h)^0.2 を 50° で 1 にした値（拡散照度 sin(h)^0.6 に順応を掛けた）、地平から −6° までは対数で 10 分の 1 に落とす。夜は 0.45 に戻す（夜の路上は空ではなく街の明かりで照らされる）。色は昼 0xbfd9ff（以前と同じ）、低い太陽で 0x86a8f0（日陰が青くなる）、薄明 0x4c62b4、夜 0x5a544e（街の光の灰橙）、雨 0xc4cfdc。
- **露出**: 昼 1、低い太陽で +0.25、薄明でさらに +0.15、夜 0.8、雨 0.95。
- **環境マップの強さ**: 昼 0.42、低い太陽 0.7、雨 0.9、夜 1。空の環境マップは太陽が低いと暗く、雨と夜はもっと暗いので、映り込みが見える空の明るさに近くなるように上げる。
- 昼（50°・晴れ）で太陽 2.8、天空光 1.5（0xbfd9ff）、露出 1 になることをテストで確かめている。[^unit]

天気は `Environment.overcast` が 25 秒かけて 0 ↔ 1 を動き、空の濁り・雲量・太陽・天空光・霧・露出・環境マップがすべてこれで補間される（おまかせで天気が変わっても段差にならない）。視程から求める減衰係数は対数で 10 秒の時定数で追う。

# 空のシェーダー（skyShader.ts）

main: Sky.js の文字列に 5 か所（アンカー）で足す。アンカーが見つからなければ例外で、`upgradeSky` は null を返して元の空のまま動く。

webgpu ブランチ: three の SkyMesh（Sky.js の TSL 版）を項ごとに写した `TokyoSky` に、同じ 5 か所を同じ位置で入れた（SkyMesh はノイズと varying をコンストラクタの中に持つので、継いで差し込めない）。追加はそれぞれの uniform の一様な分岐の中。太陽の円盤は 60000 で抑える（フレームの半精度の上限）。式と係数は下のとおりで同じ。[^webgpu-shaders]

- 雲より奥: 夜の光害（地平で GLOW、天頂でその 0.22 倍。晴れ (0.08, 0.062, 0.05)、雲の下 (0.095, 0.076, 0.062)）、星（晴れた夜だけ、仰角 15° 以上、ハッシュの格子で天球に約百個）、薄明のドーム（太陽が沈んだ側が明るく、地平に残照）、オゾンの青（太陽が低いとき、Preetham の空の青緑を青に寄せる）。
- 雲: 雲の底が街の光を返す（GLOW × 0.9 × 陰影）。
- 雲より手前: 雨の雲（天頂の放射輝度 0.26、地平へ 0.45 倍、雲のノイズでまだら、夜は街の光だけで照らされる）。
- 環境マップ専用: 空の彩度を半分にし（光としての Preetham は見た目よりずっと青い）、16 で頭打ちにし、地平の明るさの 0.4 倍の地面と、3–8° のビル群（夜は窓が点く）を描く。
- 出力の後: 地平の霞。霧と同じ σ₀ と H で σ₀·H / sin(仰角) の光学的厚さを取り、霧と同じ色・同じ太陽の光芒で、同じようにトーンマップして混ぜる。遠くの街と地平の空が一つの色に溶ける。webgpu ブランチでは霧も霞も線形のまま混ぜ、フレームの最後に一緒にトーンマップする（混ぜ方が同じなので、溶ける性質も同じ）。

# 霧の色は放射輝度

（main の WebGL 版の話。webgpu ブランチの node material は霧を線形のまま混ぜ、フレームの最後に 1 回だけトーンマップするので、霧の色の値はそのまま放射輝度として正しく出る。）

three の fog チャンクはトーンマップと sRGB 変換の**後**に霧の色を生のまま混ぜる。以前の霧の色（`new Color(0xbfd2e4)` は線形で (0.52, 0.64, 0.78)）は画面でそのまま (133, 163, 199) に出ていて、昼の地平の空（実測 238, 247, 252）より暗い青だった。いっぽう水面（water.ts）は同じ値を放射輝度として地平の反射に使っていた。atmosphere.ts で霧の色にもトーンマップと出力の変換を掛け、意味を放射輝度にそろえた。昼と雨の色の値は以前のまま（画面では昼 ~0.8 の薄い青灰に出る）。夜の霧は光害の色そのもの（以前は 0x0c1528 でほぼ黒）。

# 環境マップ（skyEnvMap.ts）

- 空は別の Sky（自分のユニフォーム）で、ゲームの空のユニフォームを写してから、CubeCamera で 256 のキューブに描き、`PMREMGenerator.fromCubemap(キューブ, 前回のターゲット)` で同じレンダーターゲットに描き直す。
- `fromScene` を使わない理由: 呼ぶたびに新しいターゲットを作る。`scene.environment` のテクスチャが別物になると、three は全材質のプログラムのパラメータを作り直す（WebGLRenderer の `materialProperties.envMap !== envMap`）。
- 太陽の円盤は描かない（放射輝度が 10⁴ 近くあり、粗い mip に輪が出る。光沢面の太陽はディレクショナルライトのハイライト）。

# ブルーム（bloom.ts）

## main（LDR のキャンバス）

キャンバスに直接描いているので、ワールドを描いた直後のフレームを `copyFramebufferToTexture` で一度コピーし（モーションブラーと同じ）、半分の解像度に 4 タップ（4×4 の箱）で縮めながら、表示値を x / (1 − 0.96·max) で疑似 HDR に戻して閾値を掛ける。クリップした画素は ~25 倍、0.85 の白い壁は ~4.6 倍になるので、昼は閾値 15（表示 0.975 以上、太陽とその眩しさ・ぎらつき）、夜は 3.6（表示 ~0.79 以上、点灯した窓・街灯・信号・ヘッドライト）。Karis 平均で 1 画素のちらつきを抑え、デュアルフィルタ（Kawase）で 1/32 まで縮めて戻し、最後に 1 タップで加算する。強さは昼 0.02、夜 0.05、雨の夜は 1.35 倍。

本物の HDR（ワールドを半精度のターゲットに描いて最後にトーンマップ）にしなかったのは、運転席の 2 パス・フロントガラスの雨・モーションブラーがすべてキャンバスに描くうえ、毎フレームの帯域が 2 倍とフルスクリーン 1 枚が増えるため。r186 の `outputBufferType`（WebGLOutput）も同じ理由で使っていない。

## webgpu ブランチ（HDR のフレーム）

フレームが線形の半精度のターゲットになった（[WebGPU への移行](webgpu-migration.md)）ので、擬似 HDR への戻しをやめ、閾値を **露出を掛けた放射輝度** にした。街のパスで、ブラー・ワイパー・車内の前。dual filter・Karis 平均・4×4 の前処理・画質の段は main のまま。

| 値           | 昼    | 夜    | 決め方                                                                                                                                                                          |
| ------------ | ----- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 閾値         | 9     | 0.55  | 昼は地平の空の最大チャンネル ~5.4 と日なたの白い壁 ~1.5 を膝ごと超える。夜は信号のレンズの LED ~1.0〜1.8・ロービーム ~1.4・街灯の灯具 ~8 より下、光害 ~0.1 より上。薄明は等比で |
| 膝           | ×0.35 | ×0.35 | main と同じ                                                                                                                                                                     |
| 持ち込み上限 | 40    | 40    | 太陽の円盤（露出前 ~6·10⁴）が連鎖を塗りつぶさないように                                                                                                                         |
| 強さ         | 0.04  | 0.30  | 雨の夜は 1.35 倍。見た目で決める値（確かめていない）                                                                                                                            |

- main の表示値の閾値（昼 0.975・夜 0.79）を ACES と露出で逆算すると、露出後で昼 ~3.6・夜 ~0.55。昼の 3.6 は地平の空の青（~5.4）を拾うので 9 にした。
- 露出後の値: 昼の地平の空は、main の実測の表示値（238, 247, 252）を露出 1 の ACES で逆算。信号は色をそのまま見せる放射輝度（ACES を逆にたどる、[WebGPU への移行](webgpu-migration.md) の「色をそのまま見せるマテリアル」）で、露出に依らず LED の点が露出後 ~1.0〜1.8、遠くでミップが LED と拡散板を平均すると 0.25〜0.33（夜の閾値の膝 0.36 より下で、にじまない）。**訂正**: 以前は「色 × 画像 ~1 に夜の露出 0.8」と書き、tests/sky.test.ts も 3.2 としていたが、レンズの画像の白（LED の点）で 0.63〜0.8、遠くの平均では 0.25〜0.31 だった（テストは 1.0 に直した）。街灯の灯具は instanceColor ×10（段階 A）。
- three の BloomNode を使わなかった理由: 5 段の分離ガウス（11 パス・最大 22 タップ）で Karis 平均が無い。
- 落とし穴: 後で差し替えるテクスチャノードが組む時に同じ仮のテクスチャを持っていると、three は 1 つの binding にまとめる（足し合わせの段とゴーストの段が同じものを読んでいた）。ノードごとに別の仮のテクスチャにした。
- テスト: tests/sky.test.ts（`bloomShare` で、昼の空と白い壁は 0、夜の信号・ロービーム・街灯は正、太陽は CAP で頭打ち、閾値は単調で等比）。[^webgpu-unit]

# レンズフレア（lensFlare.ts、webgpu ブランチ）

利用者の求めで足した。画質「レンズフレア」（あり / なし、最高・高で あり）。

- **見た目**: 太陽から画面の中心を通る線上のゴースト 7 つ（太陽側に 2、中心の向こうに 5。3 つは絞りの六角形、縁が少し明るい円盤、コーティングの色）、太陽を中心とする細い輪（半径は画面の高さの 0.42、外が赤く内が青い）、絞り 6 枚の光条（6 本とその間の細い筋、太陽からの距離で弱まる）。露出で割って足すので、目の順応で見え方が変わらない。街のパスなので、車内やワイパーの上には描かれない。
- **夜の灯り**: 街灯・ヘッドライトのゴーストを、ブルームの 1/8 の段を画面の中心で折り返して 4 つ足す（John Chapman の擬似レンズフレア）。夜（nightFactor 0.3〜0.9 で入る）だけ。
- **太陽が見えているか**（測る）: 太陽の方向 30 km 先に円盤の芯ほどの四角（探り）を空の直後に描き、フレームのアルファだけを 0 にする（色はそのまま）。手前に何かあれば不透明の 1 で塗られる。車内とガラスまで描いた後、太陽の位置の 7 タップで「(1 − アルファ) × 円盤の明るさの割合」を測って 1×1 に書き、非同期で読み戻して 0.08 s でならす。建物・木・車・地形・雲（空のシェーダーが円盤を隠す）・地平の霞（円盤が暗くなる）・運転席の屋根とピラーが、太陽を隠したときだけフレアを消す。
- **運転席**: 屋根の線より上の太陽（屋根に隠れた太陽）では出さない、と決めた。上の測り方で自動でそうなる。フロントガラス越しの太陽では出る（ガラスの不透明度 0.08 で 92%）。
- **曇り**: overcast 0.15〜0.6 で消える。太陽の高さ +2°〜−0.5° で円盤と一緒に沈む。
- 深度で判定しなかった理由: フレームの深度は MSAA で、解決されないまま（シェーダーからはサンプルごと、コピーも同じサンプル数どうしのみ）。アルファは出力パスが不透明にするので空いている。
- テスト: tests/lensFlare.test.ts（画面上の位置: 正面で中心、上は uv の y が小さい、背後と画面の外は見えない。強さの曲線: 隠れたら 0、沈むと 0、overcast 0.6 で 0、単調。探りのタップが円盤の芯の内側）。[^webgpu-unit]

- 変更前のフレーム時間（GPU 同期付き、昼・追従視点）: 50〜65 ms。マシンの負荷が平均 ~92 のヘッドレス Chrome で、差を測るのには使えなかった。ブルームの費用は測っていない。

# 踏んだ落とし穴

- **環境マップが暗いまま止まる**: 空のユニフォームを更新する前に環境マップを描き直していた（1 フレーム遅れ）。描いた時点の状態を「描いた」と覚えるので、雨→晴れの最初のフレームで雨の雲のまま描かれ、以後は差が無いとみなされて描き直されなかった。ユニフォームを先に書くように直した。
- **NaN の危険**: GLSL の `pow(x, y)` は x < 0 で未定義で、`dot(...) * 0.5 + 0.5` は丸めで負になりうる。`smoothstep` の端を逆に渡すのも未定義。半精度の環境マップに NaN が一つ入ると PMREM のフィルタで全 mip に広がる。clamp と長さの下限で守った。
- ヘッドレス Chrome のページは可視なので、自分の rAF ループが CDP の `evaluate` の合間にも回る。天気を切り替えて値を書き換える検証では、その間のフレームが先に描き直しを起こす。
