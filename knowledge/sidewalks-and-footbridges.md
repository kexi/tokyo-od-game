縁石の高さはどのデータにも無い。PLATEAU も横断方向の高さは一律と明記している。ゲームでは 15cm にした。

## ゲームでの描き方（`src/world/pavements.ts`）

- 走行地点を含む区（`areas.json` の町丁の外接矩形から求める）ごとに、3×3 の z16 タイルを読む。丸の内では千代田・中央・港の 3 区、2,320 枚の多角形になった。[^game-run]
- 1 タイルは丸の内で 331KB と大きい。地物ごとに属性の JSON 文字列を丸ごと持っているためで、形状そのものは小さい。道路網とは別に読み、道路の構築を待たせない。
- MVT のリングはタイル外のバッファまで含むので、隣のタイルと重ならないようタイルの正方形で切り取る。外周リングは y 下向きの座標で時計回り、穴は反時計回り。
- 地面の高さ＋15cm に舗装を張り、外周と穴の縁に縁石の面を立てる。Rapier の trimesh で当たり判定も付ける。
- 歩行者は、道路区間の両側を中心線から外へ 0.5m 刻みで調べ、歩道部の多角形に入る帯の中ほどを歩く。多角形の中に立つ人は 15cm 上げる。

## 落とし穴

1. **広い歩道の真ん中で車道が透けた**。広い歩道は外周の頂点しか持たないので、三角形が数十 m に広がり、頂点の間の地面の起伏に高さを合わせられなかった。車道の面（地面＋10cm、2.5m 間隔）がその下から突き出た。各三角形の重心と辺の中点で地面を調べ、舗装より高ければ三角形の頂点を持ち上げるようにした。頂点を共有したまま上げるので、面に隙間はできない。
2. **地理院の幅員と歩道の関係が区間によって違う**。丸の内では PLATEAU の歩道が、地理院の幅員で描いた車道の内側に入り込む区間があった。地理院の幅員が歩道込みの区間と見ている（確かめていない）。歩道の帯は幅員から決め打ちせず、多角形を探して決める。

[^survey] [^road-db]

点検 DB の点と OSM の線は 759 件中 627 件（83%）が 30m 以内で対応した。点検 DB の規約（第 11 条）は利用契約を結んだ人が対象で、キー無しの公開 API での二次利用の扱いは確かめていない。[^survey]

ゲームではまだ歩道橋を描いていない。描くなら、OSM の線で向きと階段の位置を決め、Blender で作った部品（桁・階段・手すり）を並べる案が有力。PLATEAU の 92 基は形状が完全だが、区が偏っている。
