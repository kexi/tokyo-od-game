# 構成

`GameAudio`（game/audio.ts）の AudioContext の上に `SpatialAudio`（game/spatialAudio.ts）を置き、計算は WebAudio を使わない `game/spatialMath.ts` に分けた（vitest で回せるように）。

```
world ─┬─ outside (1 − k) ─────────────────────────────┐
       └─ 低域通過 → 低域シェルフ → 遮音 (k × −17 dB) ─┼─ master（ミュート）→ リミッタ → 出力
interior (k): 自車のエンジン・ロードノイズ・屋根の雨 ──┤   （k の経路は車内の残響にも送る）
自車の外の音（排気・タイヤ）→ outside ──────────────────┘
```

- 聴取点はカメラ（位置と向き）。運転席視点では `DriverEye` に置かれたカメラなので、運転者の頭になる。
- 位置を持つ音源は「入力 → 空気吸収の低域通過（距離で 20 kHz → 1.5 kHz）→ PannerNode（HRTF、スマホは equalpower、`distanceModel: inverse`）」。位置は毎フレーム、物体の位置 + 物体の向きで回したオフセットから求める（物体はシーン直下にある前提）。
- 位置を持つようにした音: 救急車・パトカー（事故対応）のサイレン、巡回パトカー（白バイ・覆面を含む）の追跡中のサイレン、パトカーのスピーカーの呼びかけ（端末内の音声合成を有効にしたとき）、会話中の歩行者の声、自車の警音器、近くの車の走行音、音響式信号機の誘導音。
- 位置を持たないまま: ナビ（navGuide.ts）・スタンプ（stamp.ts）・ウインカーのリレー音・発見のチャイム・電話の相手の声。
- 他車の警音器はゲームに無い（AI の車は鳴らさない）ので作っていない。

| 音源                 | refDistance / rolloff / 届く範囲                | 位置                                                        |
| -------------------- | ----------------------------------------------- | ----------------------------------------------------------- |
| サイレン             | 20 m / 0.8 / 900 m                              | 車体の原点から上 1.0 m・前 0.4 m                            |
| パトカーのスピーカー | 8 m / 0.8 / 350 m                               | 上 1.2 m・前 0.8 m（帯域を絞って軽く歪ませ、再生速度 0.94） |
| 歩行者の声           | 3 m / 0.6 / 40 m                                | 足元から 1.55 m                                             |
| 警音器               | 3 m / 1 / 300 m                                 | 前バンパーの裏（前 2.1 m）                                  |
| 自車の排気・タイヤ   | 3 m / 1 / 200 m                                 | 後ろ 1.6 m・下 0.5 m（車外の聴取点でだけ聞こえる）          |
| 他車の走行音         | 4 m / 1.2 / 乗用車 90 m・大型 150 m・二輪 120 m | 車体の原点                                                  |
| 音響式信号機         | 3 m / 1 / 70 m                                  | 歩行者用灯器の高さ（歩道から 2.75 m）                       |

# ドップラー効果

WebAudio の `AudioListener.dopplerFactor` / `PannerNode.setVelocity` は仕様から削除されたので、自前で計算する。DelayNode の遅延時間を距離 / c で動かせばドップラーも伝搬遅延も自然に出るが、音源ごとに最大 3 秒近い遅延バッファが要り、遅延時間を毎フレーム変えると継ぎ目の雑音が出やすいので採らなかった。

- 音源から聴取点への単位ベクトルに沿って、音源の速さ v_s（聴取点へ向かう向きが正）と聴取点の速さ v_l（音源へ向かう向きが正）を取り、f′/f = (c + v_l)/(c − v_s)、c = 343 m/s。0.75〜1.33 に制限する。
- 速度は位置の差分から求め、時定数 0.12 s で平滑化する。1 フレームで 90 m/s を超える移動（浮動原点の付け替え・テレポート・カメラの切り替え）は速度にしない。車内と車外をまたぐカメラの切り替えでは聴取点の追跡を初期化する（運転席 ↔ ボンネットは約 1.2 m で、60 fps だと 72 m/s に見えるため）。
- 比は cents にして、鳴っているものの `detune`（OscillatorNode・AudioBufferSourceNode）に 50 ms の時定数で入れる。サイレンは周波数の型（ピーポー／ウー）を `frequency` に 2 秒先まで順に予約し、ドップラーは `detune` が受け持つ。
- 自車の音にはかけない。聴取点が一緒に動く（または止めた車のそば）ので相対速度はほぼ 0 で、追従カメラのばねの揺れを拾うだけになる。

理論値: 50 km/h（13.89 m/s）で近づく音源は 343/(343 − 13.89) = 1.0422、遠ざかると 343/(343 + 13.89) = 0.9611。通過で 7.8 %（1.40 半音）下がる。[^unit]

実測（救急車が聴取点の 6 m 先を 50 km/h で横切る、OfflineAudioContext 48 kHz）[^browser]:

|                      | 近づく（x = −49〜−21 m）           | 真横（x = 0） | 遠ざかる（x = 14〜49 m）         |
| -------------------- | ---------------------------------- | ------------- | -------------------------------- |
| 計算したドップラー比 | 1.0407〜1.0418（+69〜+71 cents）   | 1.0000        | 0.9638〜0.9613（−64〜−68 cents） |
| ゼロ交差で測った音程 | 960 Hz → 1,000 Hz、770 Hz → 801 Hz | —             | 960 Hz → 924 Hz、770 Hz → 740 Hz |

測った音程の比は 0.9622 / 1.0417 で 7.6 % の低下。ゲーム内（追従カメラ・5 m 横を通過・setInterval で 0.1 s ごとに読んだ値）でも +69 cents → −68 cents だった。

# 車内の音

- 車内と判断するのは、自車を運転中で、運転席視点のとき、またはカメラが車体の箱（原点から幅 ±0.78 m、高さ −0.45〜0.60 m、前後 −1.35〜+0.95 m）の中にあるとき。追従・俯瞰・ボンネットのカメラは車外（ボンネット視点は屋根より 0.5 m 上）。
- 窓を閉めた状態: 800 Hz の低域通過（Q 0.6）、220 Hz 以下を 6 dB 戻す低域シェルフ、−17 dB。運転席から歩行者と話している間は窓を開けた扱いで 5 kHz・0 dB・−5 dB。値は耳で決めたもので、実車で測っていない。
- 車内の残響: 1.2〜5.4 ms の初期反射 6 本と、時定数 8.7 ms の減衰（約 60 ms で −60 dB）の 80 ms のインパルス応答を生成し、ConvolverNode で 0.3 混ぜる。
- 自車のエンジン: 車内ではのこぎり波とその 1/2 の正弦波を 140〜260 Hz の低域通過に通した低いうなり、車外では Q 4 の低域通過（500 Hz + アクセル × 1,800 Hz + 発火周波数 × 4）と軟らかい歪みを通した排気音を車の後ろから。ロードノイズは速さの 1.5 乗で上がる帯域ノイズ（車内 240 Hz + 2 Hz/km/h 中心、車外 900 Hz 中心）。
- 雨: 車外は 2.5〜9 kHz のサーという音（world に入れるので車内では低域通過でほぼ消える）、車内は 1 秒に約 140 粒の打撃音（2 割 5 分に屋根の 180〜320 Hz の鈍い響き）の 3.7 秒のループ。どちらも log2(1 + mm/h) に比例。
- 切り替え: 外・遮音・車内の 3 つの利得を時定数 0.1 s（約 0.3 s で落ち着く）で入れ替える。

実測: 同じ通過を車内で聞くと RMS が −24.4 dBFS → −41.9 dBFS（−17.5 dB）、ピークが 0.27 → 0.045。左右の偏りは最初の 1.5 秒が R − L = −7.8 dB、最後の 1.5 秒が +7.3 dB（左から右へ動く）で、車内でも −7.3 / +6.8 dB と向きは残る。ゲーム内では運転席視点にすると outside 0・遮音 0.141・interior 1 になった。[^browser]

# 上限と割り当て

- 位置を持つ音源は同時に 12 個まで。サイレン・使用中の声（2 枠）・押している警音器・自車の排気を先に数え、残りを走行音（6 枠）と音響式信号機（4 枠）で分ける。
- 0.1 秒ごとに、届く範囲の外の候補を捨て、「音量 ÷ 距離」（inverse の法則）の大きい順に並べ、枠と全体の上限の中で取る。鳴っている音源には 1.3 倍の下駄を履かせ、ほぼ同じ大きさの 2 台の間で枠が行き来しないようにした。
- ノードは使い回す（走行音・信号機・声の枠は最初に作ったまま。サイレンだけ鳴らすときに作り、止めたら外す）。毎フレームの処理は配列や物体を作らない。AudioParam の予約は値が変わったときだけ（利得 1e-4、空気吸収 3 %、ドップラー 0.5 cents の閾値）。
- 実測: サイレン 3・警音器・排気・走行音 1 の状態で `update` 1 回 0.016 ms（ヘッドレス Chrome、M2 Max、3,000 回の平均。オーディオスレッドの負荷は含まない）。[^browser]

# 音響式信号機

- 歩行者用灯器が青（点滅でない）の間だけ、灯器の位置から鳴らす。両端の灯器が半周期（0.75 s）ずつずらして交互に鳴く（鳴き交わし）。片方の端は 1 回（「ピヨ」「カッコー」）、もう片方は 2 回（「ピヨピヨ」「カカッコー」）。
- 南北に渡る横断歩道は「ピヨ」、東西は「カッコー」（ゲーム座標は +X 東、−Z 北）。「ピヨ」は 2.7 → 3.3 → 2.2 kHz の 0.11 秒のさえずり、「カッコー」は 840 Hz → 660 Hz の下がる 3 度。
- 8 時〜19 時だけ鳴らす（夜は近隣への配慮で止める運用が多いという前提）。ゲーム内の時刻（`env.displayHour`）で判定する。

方向による鳥の割り当て・鳴き交わしの形・運用時間は記憶に基づいており、一次情報（警察庁の指針）で確認していない。地域や交差点によって「主道路と従道路」で分ける運用もあると記憶している。[^memory]

# 検証で分かったこと

1. ヘッドレス Chrome（`--autoplay-policy=no-user-gesture-required`）では AudioContext が running になり、`currentTime` が進む（44.1 kHz）。描画結果は聞けないので、`describe()` の値と OfflineAudioContext の書き出しで確かめる。
2. OfflineAudioContext は `suspend(t)` をフレームごとに先に全部予約し、その中で `update` を呼んで `resume()` すれば、ゲームと同じクラスをそのまま通せる。suspend の時刻は 128 サンプルの区切りに丸められる。
3. ゼロ交差で音程を測ると、音源が真横を通る 0.6 秒ほどは 1,357 Hz・1,054 Hz のような外れ値になった（HRTF の近距離での切り替えと考えているが、確かめていない）。通過の前後の区間では、計算したドップラー比と 0.1 % 以内で合う。
