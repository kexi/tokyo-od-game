# 何を変えたか

three r186 は影のパスで、外壁の材質の `colorNode` の alpha を影の材質に写す（`Renderer._getShadowNodes` の `hasColorNode`）。外壁の `colorNode` は `surface()` の `Fn` で、窓の点灯・部屋の奥行き・雨・テクスチャ・微分を組み立てるので、alpha を読むだけのために影のシェーダーにそれが全部入っていた。perf-baseline.md の帰属（p0-attr-1、main 48dc699）で、最長の 533〜567 ms のフレームの約 400 ms がこの影のパスの組み立てで、中に外壁の TSL（`lampColour`・`hash12`）が出ていた。

`src/world/facade.ts` の `surface()` は、組み立てている材質が three の影の材質（`isShadowPassMaterial`）なら、すぐ `vec4(0, 0, 0, 1)` を返す。外壁の alpha は常に 1 なので、影は同じになる。[^tests]

採らなかった方法:

- `material.castShadowNode`: three は castShadowNode があっても影の alpha に `colorNode.a` を掛けるので色の段は組み立てられる。さらに `shadowMap.transmitted` が無いと警告を出す。
- 影用の材質を別に持つ: 影のパスの材質は three がライトごとに 1 つ選び、こちらの材質からノードを写す。差し替える口が無い。

# 計測

測った版は、すべて作業木の外の with-server.sh v4 で確かめた: 望む commit が HEAD で、src など配る物に未コミットの変更が無く、ポートの待ち受けが全部自分の立てた vite で、`__log/build` の label がその木の label と同じ。走りの後も label と、走りの間のセッションのログの build を照らした（前に「main」と書いた p0-attr-3 は別の作業木を測っていたので、この文書では使わない。perf-baseline.md）。

## 8 棟の影の組み立て（just measure-facade-shadows、1 本）

旧処理（A）と新しい処理（B）を条件ごとに描いた。値は 8 棟の影の材質を組み立てる CPU（ms）と、組み立てた fragment の長さ（字）。[^parity]

| 描画方式 | 窓    | 昼 A → B   | 夜 A → B   | fragment A → B |
| -------- | ----- | ---------- | ---------- | -------------- |
| WebGPU   | flat  | 18.7 → 1.5 | 13.9 → 1.2 | 6,941 → 855    |
| WebGPU   | lit   | 34.4 → 1.7 | 32.4 → 1.8 | 20,402 → 855   |
| WebGPU   | rooms | 32.1 → 1.4 | 32.9 → 1.2 | 20,402 → 855   |
| WebGL2   | flat  | 15.4 → 2.0 | 13.5 → 1.8 | 6,278 → 1,118  |
| WebGL2   | lit   | 31.7 → 1.5 | 31.5 → 1.7 | 17,904 → 1,118 |
| WebGL2   | rooms | 33.4 → 1.4 | 35.3 → 1.6 | 17,904 → 1,118 |

- 一致: 12 条件の、建物を動かす前に描いた画像と、動かした状態から描き始めた画像の 24 組で、409,600 の値が全部同じ（差 0）。影の有無で画素が変わることも確かめた。
- 近道が取られたこと: 12 条件とも、新しい影の fragment が古い物の最短より短い（parity の valid に入れた）。three が影のパスで自分の override を builder.material として渡すことは単体テストでは見えないので、これは `just measure-facade-shadows` を走らせたときだけ効く。
- **動かした後の WebGPU の差（もとからの癖）**: 建物を動かした後の A と B は、WebGPU の 3 条件で 873〜1,405 値違う（差の最大 24 = その条件の影の有無の差の最大と同じ）。WebGL2 は 0。旧のコードだけでも同じ形で出る: A の中で、描いてから動かした画像と、動かした状態から描いた画像（同じ場面のはず）が、WebGPU の 4 条件で 1,397〜1,539 値違う。出る条件は走りと A・B でずれる。WebGPU で、動いた物の影の更新が描き方の時間に依って遅れる、もとからの癖と読む（原因は調べていない）。この変更のせいではない: 外壁の影の alpha は式の上で 1 で、discard・alphaTest・mask が無い。

# 確かめていないこと

- WebGPU で、動かした後の影が描き方の時間で違う理由（もとからの癖と見た）。
- 影の質（PCF の縁など）の主観の見え方。画素は 8 棟の場面で一致を見ただけで、ゲームの街並みでは撮っていない。
- 本物のスマホ（低の画質は建物の影が無いので効かない）。
- 判定の線（プロファイラなしの最長フレーム）での効き。マージ後の取り直しで見る。#140 が入ると最長が下がるので、基準と線を取り直すかは計画の判断（Fable）。
